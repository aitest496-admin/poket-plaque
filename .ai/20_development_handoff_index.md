# 本開発引き継ぎ資料 インデックス

この資料群は、Smart Perio Chart のPOCを本開発へ移行するために、開発者へ渡す前提で整理したものです。

## 資料の役割

| ファイル | 役割 |
|---|---|
| `21_requirement_definition_for_development.md` | 本開発向けの要件定義書。目的、対象ユーザー、機能要件、非機能要件、受け入れ条件をまとめる。 |
| `22_screen_and_workflow_spec.md` | 画面構成と主要な操作フロー。iPad縦持ちでの入力効率を重視する。 |
| `23_data_and_business_rules.md` | 保存データ、業務ルール、計算・入力値の扱い。 |
| `24_open_questions_for_development.md` | 本開発前に決めるべき未決事項、開発者への確認項目。 |

## 本開発者へ最初に伝えること

- 現在のアプリはPOCであり、主にフロントエンドの操作感と必要機能を確認するためのもの。
- 本開発では、POCの画面や実装をそのまま製品化するのではなく、業務要件を満たすために再設計してよい。
- ただし、iPad縦持ちで少ないタップ数で入力できることは最重要要件。
- ポケット入力は9mmまでを目盛りで表示し、10mm以上は手入力する方針。
- ターゲット端末は iPad 第8世代、物理解像度 2160 x 1620px。縦持ち利用を優先する。

## 本開発の進め方の推奨

1. `21_requirement_definition_for_development.md` をもとに開発範囲を確定する。
2. `24_open_questions_for_development.md` の未決事項を医院側・開発者側で確認する。
3. 画面設計は `22_screen_and_workflow_spec.md` を起点に、実機iPadでプロトタイプ確認する。
4. データベース設計は `23_data_and_business_rules.md` を起点に、患者管理・権限・バックアップ要件を追加する。
5. 本実装前に、入力画面だけを先に実機検証し、タップ数・誤入力・1画面収まりを確認する。
