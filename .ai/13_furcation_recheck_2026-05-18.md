# 2026-05-18 6点法・根分岐部病変追加後の再検証

対象URL: https://aitest496-admin.github.io/poket-plaque/

検証者: Codex

注意: Codexはシステム本体の修正を行わない。今回も `.ai` 配下の検証メモのみ更新し、アプリ本体ファイルは変更しない。

## 検証観点

- 6点法に追加された根分岐部病変の入力ができるか
- 入力した根分岐部病変が保存後の6点法プレビューに反映されるか
- 既存仕様である「ポケット目盛りは9mmまで、10mm以上は手入力」が維持されているか
- iPad第8世代縦向き相当の表示で、入力画面とプレビューに大きな崩れがないか
- PISAプレビューや既存画面が根分岐部病変追加で壊れていないか

## 確認できたこと

- 6点法の入力画面に `分岐部` 行が追加されている。
- 臼歯部の根分岐部セルをタップすると、未入力 -> `Ⅰ` -> `Ⅱ` -> `Ⅲ` -> 未入力の順で切り替わる。
- `Ⅲ` を入力して保存すると `保存しました` が表示される。
- 6点法プレビューに `根分岐部病変を表示する` チェックボックスが追加されている。
- チェックをオンにすると、プレビュー表に `根分岐部` 行が表示され、入力した `Ⅲ` が反映される。
- 6点法の入力画面ではポケット目盛りが1〜9までで維持され、10以上の目盛りは表示されない。
- iPad第8世代縦向き相当のCSS viewport `810 x 1080px` で、1点法・4点法・6点法の入力画面に横スクロールは出なかった。
- PISAプレビューは表示でき、未入力時は `未入力のため評価できません` と `評価不可` が表示される。
- ブラウザコンソールの warning / error は確認されなかった。

## 気になった点

### 1. プレビューの根分岐部表示が初期OFF

根分岐部病変を入力して保存しても、6点法プレビューを開いた直後は `根分岐部病変を表示する` がOFFだった。チェックを入れれば表示されるため機能自体は動作している。

ただし、根分岐部病変が入力済みなのに初期状態で見えないと、プレビュー確認者が入力漏れと誤解する可能性がある。

推奨:

- 根分岐部病変データが1件でも存在する場合は、プレビュー初期表示でチェックONにする。
- もしくは、チェックOFFでも `根分岐あり` の小さなバッジを表示し、非表示になっていることが分かるようにする。

### 2. 入力画面のラベルが `分岐部`

省スペースのためだと思われるが、入力画面の行ラベルは `分岐部`、プレビューの切替文言は `根分岐部病変` になっている。

推奨:

- 画面幅に余裕がある場合は入力画面も `根分岐部` にする。
- iPad縦向きで幅が厳しい場合は `分岐部` のままでもよいが、ツールチップや長押し説明などで `根分岐部病変` と分かるようにする。

### 3. iPad縦向き相当でプレビュー幅がやや大きい可能性

CSS viewport `810 x 1080px`、6点法プレビュー、根分岐部表示ON、ズーム70%の状態で、チャート本体の計測幅が約834pxとなり、viewport幅810pxより約24px大きい状態だった。ページ全体の横スクロールは出ていないが、端がわずかに詰まる可能性がある。

推奨:

- iPad第8世代縦向きでは、根分岐部表示ONの6点法プレビューが横幅内に完全に収まるようにする。
- 具体的には、プレビューのデフォルトズームを少し下げる、または `max-width: calc(100vw - 余白)` に収める。
- 印刷用の見た目は維持しつつ、画面プレビュー時だけ横幅に収める。

## 追加で実機確認したいこと

- iPad第8世代実機の縦向きで、6点法入力画面の根分岐部セルがタップしやすいか。
- 根分岐部病変を複数歯に入れた場合、プレビューで見分けやすいか。
- 根分岐部表示ONの6点法プレビューがiPad縦向きで端まで完全に見えるか。
- 10mm以上のポケット手入力、保存、読込、プレビュー、PISA反映が引き続き問題ないか。

## 総合判定

根分岐部病変の基本機能は動作している。入力、段階切替、保存、6点法プレビュー反映は確認できた。

大きな機能バグは確認されなかったが、プレビュー初期表示とiPad縦向きでのプレビュー横幅は、実運用前に調整した方がよい。
